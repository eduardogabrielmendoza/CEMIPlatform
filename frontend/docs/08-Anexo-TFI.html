Tipo: investigación, relevamiento de requerimientos funcionales y no funcionales.

  • Conocer las necesidades actuales de gestión académica, administrativa y comunicacional del centro.

Análisis y Documentación de Entrevista

Conclusiones

  • El proyecto tiene como objetivo desarrollar un sistema informático para la gestión integral del centro de idiomas CEMI.
  • La entrevista permitió identificar problemas de centralización, trazabilidad, comunicación y disponibilidad de información académica.
  • Se definieron módulos de administración, classroom, pagos, calificaciones, asistencias, comunidad, seguridad y chat.
  • La solución se implementa como aplicación web responsive, con persistencia en MySQL y despliegue en Railway.
  • El sistema contempla roles diferenciados para alumnos, profesores, administradores e invitados.

Definición del Problema

El Centro de Estudios Multilingüe Internacional requiere una plataforma que unifique procesos académicos, administrativos y de comunicación. Sin un sistema centralizado, la información de alumnos, cursos, inscripciones, pagos, calificaciones y comunicaciones queda dispersa, generando demoras, errores de registro y dificultad para consultar el estado real de cada operación.

La ausencia de un entorno virtual propio también limita el seguimiento de tareas, anuncios, encuestas, recursos y conversaciones entre profesores y alumnos.

Elemento - Descripción

ElementoDescripción
El problemaFalta de un sistema web unificado para gestionar información académica, financiera y comunicacional de CEMI.
Afecta aDirección, administración, profesores, alumnos e invitados que solicitan soporte o inscripción.
Resultados actualesProcesos fragmentados, baja trazabilidad, dificultad para consultar pagos, inscripciones, tareas y novedades.
Beneficios esperadosCentralización de datos, automatización operativa, classroom integrado, comprobantes, reportes, comunicación en tiempo real y mejor experiencia de usuario.

Identificación de Clientes y Usuarios

  • Cliente principal: Centro de Estudios Multilingüe Internacional.
  • Usuarios administrativos: gestionan alumnos, profesores, cursos, inscripciones, pagos, reportes, soporte y configuración.
  • Profesores: administran classroom, anuncios, tareas, calificaciones, asistencias, recursos y comunicación con alumnos.
  • Alumnos: consultan cursos, pagos, calificaciones, tareas, anuncios, calendario, comunidad y chats.
  • Invitados: pueden consultar información pública y contactar soporte.

Límites de la Solución

La solución informatiza la gestión académica y administrativa del centro, incluyendo autenticación, roles, alumnos, profesores, cursos, idiomas, niveles, aulas, inscripciones, pagos, comprobantes, calificaciones, asistencias, classroom, comunidad, notificaciones, chat y módulos de seguridad. Quedan fuera de alcance inicial la facturación fiscal externa, la emisión oficial de certificados con firma digital y una aplicación móvil nativa independiente.

Limitaciones

  • Técnicas: requiere conexión a Internet y disponibilidad del servicio Railway y base de datos MySQL.
  • Operativas: la carga inicial de datos debe ser realizada por usuarios administrativos autorizados.
  • Humanas: los usuarios necesitan una capacitación básica para operar correctamente los módulos.
  • Temporales: el proyecto se planificó en etapas iterativas durante el período académico 2025.

1. Introducción

Este documento se basa en la estructura de una Especificación de Requisitos de Software. Define los requisitos funcionales, no funcionales, reglas de negocio, trazabilidad y criterios de aceptación del Sistema de Gestión Académica CEMI.

1.1 Propósito

Especificar de manera clara, verificable y completa las condiciones que debe cumplir el sistema para resolver la gestión académica, administrativa, financiera y comunicacional del Centro de Estudios Multilingüe Internacional.

1.2 Alcance

  • Gestión de alumnos, profesores, administradores, cursos, idiomas, niveles y aulas.
  • Registro de inscripciones, pagos, cuotas y comprobantes PDF.
  • Administración de calificaciones, asistencias y reportes.
  • Classroom con tareas, entregas, anuncios, encuestas, calendario, recursos y chats.
  • Chat de soporte con invitados, alumnos y profesores.
  • Autenticación, recuperación de cuenta, seguridad, privacidad y roles.

1.3 Objetivo General

Desarrollar una plataforma web que permita gestionar de forma eficiente e integrada las operaciones académicas y administrativas de CEMI, garantizando persistencia, trazabilidad, seguridad y accesibilidad desde distintos dispositivos.

2. Descripción General

CEMI es una aplicación web con arquitectura cliente-servidor. El frontend se desarrolla con HTML, CSS y JavaScript; el backend utiliza Node.js y Express; la base de datos es MySQL; la comunicación en tiempo real se implementa con Socket.IO y el despliegue se realiza en Railway.

3.3 Reglas de Negocio

  • RN1. Un alumno debe existir antes de registrar una inscripción.
  • RN2. Una inscripción debe asociarse a un curso válido y activo.
  • RN3. Un pago debe asociarse a un alumno, curso, concepto y medio de pago.
  • RN4. Las cuotas disponibles pueden limitarse por curso mediante configuración.
  • RN5. Solo profesores autorizados pueden publicar tareas y anuncios en sus cursos.
  • RN6. Solo usuarios autenticados pueden acceder a dashboards privados.
  • RN7. Un profesor solo debe gestionar calificaciones y asistencias de cursos asignados.
  • RN8. Los mensajes de chat deben conservar historial y estado de lectura.
  • RN9. Las cuentas de staff deben respetar el dominio institucional reservado.
  • RN10. Las operaciones sensibles deben quedar protegidas por rol y token.

3.6 Criterios de Aceptación

  • El sistema permite iniciar sesión y redirigir según el rol correspondiente.
  • Los alumnos, profesores, cursos e inscripciones persisten correctamente en la base de datos.
  • Los pagos generan estado, concepto y comprobante asociado.
  • Classroom permite publicar tareas, anuncios, entregas, comentarios y eventos.
  • El chat conserva conversaciones, mensajes, adjuntos y estados.
  • La documentación del sistema se visualiza correctamente desde Documentación.
